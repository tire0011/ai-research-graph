# Interoperable sources and services

**Question:** Can a third-party catalogue, service, module or agent connect via documented APIs?

**Success test:** Prove one end-to-end import/export with source and permission boundaries.

| Platform | Evidence status | Source-backed observation |
| --- | --- | --- |
| [AI-on-Demand (AIoD)](https://www.aiodp.ai/) | documented | AIoD Metadata Catalogue has an official REST API and Python SDK, suitable for a future read-only adapter evaluation. [Official source](https://aiondemand.github.io/AIOD-rest-api/) |
| [EOSC EU Node](https://open-science-cloud.ec.europa.eu/) | documented | Contributor onboarding accepts eligible mature research tools, services and catalogues under review; not an unconditional publication API. [Official source](https://open-science-cloud.ec.europa.eu/contributors) |
| [AI4EOSC](https://ai4eosc.eu/) | documented | Modules expose a common API and can be deployed to local or federated resources; standard DEEPaaS integration is documented. [Official source](https://docs.ai4eosc.eu/en/latest/advanced/api.html) |
| [EOSC-ARENA](https://arena.ai4eosc.eu/) | planned | Project plans plug-in agent orchestration and interoperability integrated with EOSC and AI4EOSC. [Official source](https://arena.ai4eosc.eu/platform-overview/) |
